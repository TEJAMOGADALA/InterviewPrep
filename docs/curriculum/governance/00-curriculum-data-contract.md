# PrepOS Curriculum Data Contract

Version: 1.0

Status: Canonical

Owner: PrepOS Architecture Team

---

# Purpose

This document defines the canonical data contract that every curriculum document
must follow.

All curriculum documents are parsed into a standard JSON structure consumed by:

- Roadmap
- AI Mentor
- Revision Engine
- Interview Engine
- Career Intelligence
- Analytics
- Company Learning Paths

This document is the single source of truth for curriculum serialization.

---

# Hierarchy

Every curriculum follows this hierarchy.

Subject

↓

Level

↓

Module

↓

Topic

↓

Subtopic

↓

Learning Unit

---

# Curriculum Levels

Every subject contains exactly five learning levels.

1. Foundations
2. Basic
3. Intermediate
4. Advanced
5. Expert

No topic should skip prerequisite levels.

---

# Canonical Topic Schema

Every topic MUST contain the following metadata.

| Field | Required | Description |
|--------|----------|-------------|
| id | Yes | Globally unique topic id |
| title | Yes | Display name |
| level | Yes | Foundations → Expert |
| module | Yes | Parent module |
| subject | Yes | Parent subject |
| estimatedHours | Yes | Learning effort |
| difficulty | Yes | Beginner / Easy / Medium / Hard / Expert |
| prerequisites | Yes | List of required topic ids |
| learningObjectives | Yes | Expected outcomes |
| interviewImportance | Yes | Low / Medium / High / Critical |
| frequency | Yes | Interview frequency |
| companies | Yes | Company mappings |
| resources | Optional | External references |
| tags | Yes | Search tags |
| revisionWeight | Yes | Revision priority |
| status | Runtime | User progress |
| masteryScore | Runtime | Generated by AI |
| confidenceScore | Runtime | Generated by AI |

# Runtime Fields

These fields are NOT stored in markdown.

They are generated by the application.

- masteryScore
- confidenceScore
- revisionCount
- nextRevisionDate
- weakArea
- lastStudied
- streak
- bookmarked
- favorite

---

# Dependency Rules

A topic may depend on multiple prerequisite topics.

Example

Trees

↓

DFS

↓

Binary Tree DFS

↓

Lowest Common Ancestor

Parser must validate

- Missing dependencies
- Circular dependencies
- Invalid ids

# Parser Responsibilities

The parser must

- Parse markdown
- Validate schema
- Validate ids
- Validate dependencies
- Generate canonical JSON
- Report validation errors
- Preserve ordering
